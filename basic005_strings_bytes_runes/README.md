# 문자열, byte, rune: Go의 UTF-8 이해하기

## 한 줄 요약
Go에서 `string`은 **읽기 전용 바이트열**입니다. 한글(한 글자)은 UTF-8 인코딩에 따라 3바이트를 차지하며, 인덱스로 접근할 때 이 '바이트 경계'를 모르면 문자가 깨집니다.

## 왜 필요한가
Python이나 JavaScript, Java를 쓴 개발자라면 "문자열의 n번째 글자"를 `s[n]`처럼 간단히 접근할 수 있다고 배웠을 것입니다. 하지만 Go에서는 `s[1]`이 '두 번째 글자'가 아닙니다. `s[1]`은 '두 번째 바이트'를 의미합니다.

Go가 이렇게 설계한 이유는 **명확성과 효율성** 때문입니다. Go는 문자열을 "텍스트"가 아니라 "데이터의 연속"인 바이트열로 봅니다. UTF-8은 가변 길이 인코딩이기 때문에, 첫 번째 글자가 1바이트(ASCII)일 수도, 3바이트(한글)일 수도, 4바이트(이모지)일 수도 있습니다. Go 컴파일러는 "이 인덱스가 글자의 시작인가?"를 알 수 없으므로, 임의로 글자를 잘라내지 않습니다. 대신 개발자에게 `unicode/utf8` 패키지나 `for range` 루프를 사용해 **명시적으로** 문자 경계를 찾도록 요구합니다. 이는 버그를 방지하고, 성능적인 오버헤드를 최소화하기 위한 Go다운 결정입니다.

다른 언어에서는 내부적으로 문자열을 유니코드 코드로포인트 배열처럼 관리하는 경우가 많지만, Go는 메모리 상에서는 그냥 바이트의 나열일 뿐입니다. 이 차이를 이해해야 "인덱스로 자르는데 왜 글자가 반으로 잘렸지?"라는 함정에 빠지지 않습니다.

## 기본 사용

### 1. len()은 '바이트 수'를 반환한다
```go
s := "한글"
fmt.Println(len(s)) // 6
```
`len()`은 문자열의 바이트 수를 반환합니다. 한글 1글자는 UTF-8 기준 3바이트이므로, '한글' 2글자는 6바이트입니다. 반면 실제 글자 수( rune 수)는 2입니다.

### 2. for range는 자동으로 rune 단위로 돈다
```go
for i, r := range "한글" {
    fmt.Printf("%d: %c\n", i, r)
}
// 출력:
// 0: 한
// 3: 글
```
`for range`를 문자열에 사용하면 Go가 자동으로 UTF-8을 디코딩해 각 문자(rune)와 그 문자가 시작된 **바이트 인덱스**를 반환합니다. `i`는 0, 3처럼 건너뛰며increment되는 것에 주목하세요.

### 3. 인덱싱은 바이트 단위다 (위험!)
```go
s := "한글"
fmt.Println(s[0]) // '한'의 첫 번째 바이트 (126 or 228 등)
fmt.Println(s[1]) // '한'의 두 번째 바이트
fmt.Println(s[2]) // '한'의 세 번째 바이트
fmt.Println(s[3]) // '글'의 첫 번째 바이트
```
`s[2:]`처럼 인덱스를 사용하면, '한'의 중간에서 잘려나가므로 유효하지 않은 문자열이 생성됩니다.

### 4. []byte와 []rune 변환
```go
// string -> []rune (글자 목록으로 변환)
runes := []rune("한글")

// string -> []byte (바이트 목록으로 변환)
bytes := []byte("한글")

// []rune -> string (다시 문자열로)
s := string(runes)
```
변환 비용이 발생합니다. `[]rune`으로 변환하면 새로운 슬라이스를 할당하고 각 rune을 복사해야 하므로, 대량의 문자열을 자주 처리할 때는 주의가 필요합니다.

## 실전에서는 이렇게 쓴다

### 1. 문자열의 n번째 글자 찾기
```go
func getNthRune(s string, n int) (rune, int) {
    for i, r := range s {
        if n == 0 {
            return r, i
        }
        n--
    }
    return 0, -1
}
```
`for range`를 사용해 rune 단위로 반복하면서 원하는 위치의 문자를 찾습니다. `i`는 그 문자가 시작된 바이트 인덱스입니다.

### 2. 문자열 뒤집기 (palindrome 체크 등)
```go
func reverse(s string) string {
    runes := []rune(s)
    for i, j := 0, len(runes)-1; i < j; i, j = i+1, j-1 {
        runes[i], runes[j] = runes[j], runes[i]
    }
    return string(runes)
}
```
`[]rune`으로 변환한 후 인덱스로 교환합니다. `[]byte`로 하면 한글이 반으로 잘릴 수 있습니다.

## 흔한 실수

### 1. 인덱스로 자르면 한글이 깨진다

**무엇을 했는지:**
```go
s := "한글"
part := s[1:] // '한'을 건너뛰고 '글'을 얻고 싶어서
```

**어떤 일이 벌어지는지:**
`'한'`은 UTF-8으로 `e5 a5 bd` (3바이트)입니다. `s[1]`은 `a5` (두 번째 바이트)를 가리킵니다. `s[1:]`는 `a5 bd` + `'글'의 바이트들`로 구성된 유효하지 않은 UTF-8 문자열이 됩니다. 이 문자열을 출력하면 `���글` 같은 이상한 문자가 보일 수 있습니다.

**왜 그런지:**
`len("한")`은 3이기 때문에, '두 번째 글자'의 시작은 인덱스 3입니다. 인덱스 1이나 2는 글자의 중간입니다.

**고친 코드:**
```go
s := "한글"
_, i := utf8.DecodeRuneInString(s) // 첫 번째 글자 '한'의 길이(3)만큼 i를 앞으로
part := s[i:] // s[3:] -> "글"
```
`utf8.DecodeRuneInString`을 사용해 글자 하나를 읽고, 그 글자의 바이트 크기를 알아낸 뒤 슬라이싱해야 합니다.

### 2. len(string)로 글자 수를 세려고 한다

**무엇을 했는지:**
```go
s := "안녕하세요"
fmt.Println(len(s)) // 15 (바이트 수)
// 사람들은 5를 기대합니다.
```

**어떤 일이 벌어지는지:**
`len(s)`는 15를 반환합니다. 글자 수는 5입니다.

**왜 그런지:**
Go의 `len()`은 언제나 바이트 수를 반환합니다. 문자열이 ASCII만 포함한다면 1글자=1바이트이므로 문제가 없지만, 한글·중국어·일어 등 UTF-8로 2~4바이트를 쓰는 문자가 포함되면 다릅니다.

**고친 코드:**
```go
import "unicode/utf8"

s := "안녕하세요"
fmt.Println(utf8.RuneCountInString(s)) // 5
```
`unicode/utf8` 패키지의 `RuneCountInString`을 사용하세요.

### 3. string을 []byte로 변환 후 인덱스로 접근한다

**무엇을 했는지:**
```go
s := "한글"
bytes := []byte(s)
fmt.Println(bytes[1]) // 2 바이트째의 값을 본다
```
이것 자체는 오류는 아닙니다. 하지만 "bytes[1]이 두 번째 글자다"라고 생각하면 잘못입니다.

**왜 그런지:**
`[]byte`는 여전히 바이트의 나열입니다. '한'의 첫 번째 바이트는 `bytes[0]`, 두 번째는 `bytes[1]`, 세 번째는 `bytes[2]`입니다. '글'의 첫 번째 바이트는 `bytes[3]`입니다.

**고친 코드:**
글자 단위로 접근해야 한다면 `[]rune`으로 변환하세요.
```go
runes := []rune(s)
fmt.Println(runes[1]) // '글' rune 값
```

### 4. string concatenation을 반복문에서 += 로 한다

**무엇을 했는지:**
```go
var s string
for i := 0; i < 1000; i++ {
    s += "a" // 매번 새로운 string을 할당합니다.
}
```

**어떤 일이 벌어지는지:**
`string`은 불변(immutable) 타입입니다. `+=`를 할 때마다 새로운 문자열을 만들고 이전 내용을 복사해야 하므로, 성능이 O(n²)로 떨어질 수 있습니다.

**왜 그런지:**
Go의 `string`은 읽기 전용 바이트열이라, 변경할 때마다 새 메모리를 할당합니다.

**고친 코드:**
`strings.Builder`를 사용하세요.
```go
var sb strings.Builder
for i := 0; i < 1000; i++ {
    sb.WriteString("a")
}
s := sb.String()
```

## 주의할 점

- **인덱스로 자를 때 경계 확인**: `s[i:]`를 사용할 때 `i`가 유효한 UTF-8 문자의 시작점인지 반드시 확인하세요. `utf8.ValidOffset(s, i)` 함수를 사용하면 인덱스 `i`가 유효한 rune 시작점인지 확인할 수 있습니다.
- **[]byte <-> []rune 변환 비용**: 이 변환은 메모리 할당과 데이터 복사를 수반합니다. 루프 내부에서 빈번하게 호출되면 성능 병목이 될 수 있습니다. 가능하면 한 번 변환해 두고 재사용하거나, `utf8` 패키지 함수를 활용해 바이트 단위에서 처리하는 것을 고려하세요.
- **비ASCII 문자열의 length**: `len()`과 `utf8.RuneCountInString()`의 차이를 항상 염두에 두세요. 슬라이스 길이를 기준으로 루프를 돌릴 때 `len()`을 쓰면 바이트만큼 돌고, rune 수만큼 돌리려면 `RuneCountInString`을 써야 합니다.
- **string indexing은 byte indexing이다**: `s[i]`는 언제나 `i`번째 바이트를 반환합니다. 이것이 rune의 시작 바이트인지 아닌지는 Go가 보장하지 않습니다.

## 코드로 확인하기

`go run .`을 실행하면 다음과 같은 출력이 나옵니다.

```
=== UTF-8과 한글: 문자열의 실제 모습 ===
"한글" -> e5 a5 bd e9 80 b7 
  -> '한글'은 2글자이지만, len()은 6을 반환합니다. 각 한자 글자가 UTF-8로 3바이트이기 때문입니다.

=== 인덱싱 함정 ===
[실수 버전] 인덱스 2부터 잘라내기:
  결과: "�글" (이건 '글'이 아닙니다! 깨진 문자열입니다)

[고친 버전] 올바른 UTF-8 경계에서 자르기:
  결과: "글" (올바르게 '글'만 잘렸습니다)
```

- **"실수 버전"**은 `s[2:]`를 사용했습니다. '한'의 3번째 바이트(`bd`)부터 '글'의 바이트열(`e9 80 b7`)을 합쳤으므로, `bd e9`는 유효한 UTF-8 문자가 아닙니다. 따라서 출력 시 깨진 문자(`�`)가 나타납니다.
- **"고친 버전"**은 `utf8.DecodeRuneInString`으로 첫 번째 글자 '한'의 바이트 길이(3)를 얻은 뒤 `s[3:]`로 잘랐습니다. 따라서 '글'이 정확히 출력됩니다.

테스트에서는 `TestUnsafeByteAccess`가 '실수 버전'이 '글'이 아닌 이상한 값을 반환하는지를, `TestSafeByteAccess`가 '고친 버전'이 정확히 '글'을 반환하는지를 검증합니다.

## 연습 문제

1. **쉬움**: `reverse` 함수를 구현하세요. `[]rune`으로 변환해 뒤집은 후 `string`으로 변환하는 방식을 사용합니다.
2. **중간**: 문자열에서 특정 rune(예: '한')이 몇 번 등장하는지 세는 함수 `countRune(s string, r rune) int`를 구현하세요. `for range`를 사용하세요.
3. **어려움**: `[]rune` 슬라이스에서 인덱스 `i`번째 rune을 제거하고 새로운 `string`을 반환하는 `removeRuneAt(s string, i int) string`을 구현하세요. 인덱스 `i`가 유효하지 않을 때는 어떻게 처리할지 고려하세요.
