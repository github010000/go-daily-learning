# Day 49: 빌드 태그와 init 함수

## 개념 설명
Go 언어는 빌드 태그(`//go:build`) 를 통해 플랫폼, 버전, 커스텀 조건에 따라 코드를 선택적으로 컴파일할 수 있습니다. 예를 들어 `//go:build linux` 태그가 붙은 파일은 리눅스 환경에서만 컴파일 대상이 되며, 이를 통해 OS 에 따라 다른 구현체를 분리할 수 있습니다.

`init()` 함수는 일반 함수와 달리 파라미터와 반환값이 없으며, 프로그램 실행 전 자동으로 호출되는 특수 함수입니다. 패키지가 로드될 때 `init()` 함수가 실행되어 전역 변수 초기화, 설정 로드, 데이터베이스 연결 등의 준비 작업을 수행합니다.

여러 `init()` 함수가 정의되어 있을 경우, 파일은 파일 이름의 알파벳 순서로 로드되고, 파일 내에서는 함수가 정의된 순서대로 `init()` 이 실행됩니다. `main()` 함수는 모든 `init()` 함수가 완료된 이후에 호출되므로, 초기화 로직이 `main()` 앞에 실행됨을 보장할 수 있습니다.

`init()` 함수는 초기화에 유용하지만, 실행 순서가 코드 순서에 의존하고 디버깅이 어려울 수 있어 남용하지 않는 것이 좋습니다. 필수적인 전역 상태 초기화나 패키지 로딩 검증용으로만 사용하고, 복잡한 로직은 별도의 함수로 분리하여 `main()` 에서 명시적으로 호출하는 것이 바람직합니다.

## 코드 설명
- `func init()`: 세 가지 초기화 단계를 정의하여 실행 순서를 보여줍니다. 첫 번째는 기본 환경 확인, 두 번째는 데이터베이스 연결, 세 번째는 조건부 모드 설정입니다.
- `func init() (조건부 실행)`: `os.Args` 를 확인하여 빌드 태그의 조건부 컴파일 개념을 시뮬레이션합니다. 실제 빌드 태그는 파일 앞에 주석으로 작성됩니다.
- `func main()`: 모든 `init()` 함수가 실행된 후 호출되며, 애플리케이션의 주요 로직을 시작합니다. 출력 순서를 통해 초기화 함수들의 실행 순서가 보장됨을 확인할 수 있습니다.

## 핵심 포인트
- `//go:build` 태그는 파일 단위 조건부 컴파일을 지원하여 OS 및 버전별 코드 분리를 가능하게 합니다.
- `init()` 함수는 파일 내 정의 순서와 파일 이름 알파벳 순서에 따라 실행 순서가 결정됩니다.
- `main()` 함수는 모든 `init()` 함수가 완료된 이후 호출되며, 초기화 단계는 `main()` 앞에 실행됨이 보장됩니다.
- `init()` 함수의 순서 의존성을 피하기 위해 복잡한 로직은 `init()` 내부에서 분리하고, 필요시 `main()` 에서 명시적으로 호출하는 구조를 권장합니다.
