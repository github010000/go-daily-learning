# Day 46: 모듈과 패키지 관리

## 개념 설명
Go 언어의 모듈 시스템(Go Modules)은 의존성 관리의 표준 방식입니다. `go.mod` 파일은 모듈의 메타데이터와 의존성 목록을 포함하며, `go.sum` 파일은 다운로드된 패키지의 해시값을 저장하여 보안을 강화합니다. `go mod init`로 모듈을 초기화하면 프로젝트가 독립적인 빌드 단위가 되며, `go mod tidy`는 코드에서 참조하지 않는 의존성을 제거하고 누락된 의존성을 추가합니다.

내부 패키지(`internal`)는 모듈 내부에서만 접근 가능한 특수 디렉토리입니다. 이 폴더 안에 있는 패키지는 다른 모듈에서 import할 수 없으므로, 모듈의 public API를 안정적으로 유지하고 리팩토링 시 외부 영향범위를 제한할 수 있습니다. 이는 대규모 프로젝트에서 코드 구조를 관리하는 핵심 패턴입니다.

`replace` 지시어는 `go.mod` 파일에서 의존성을 다른 버전이나 로컬 경로로 교체할 수 있게 합니다. 주로 의존성 버그 수정이나 내부 라이브러리 마이그레이션 시 사용되며, `go mod vendor` 명령어로 의존성 패키지를 프로젝트 내 `vendor` 폴더에 복사할 수 있습니다. 이를 통해 인터넷 연결 없이 빌드하거나 CI/CD 환경의 안정성을 높일 수 있습니다.

패키지 네이밍은 소문자를 사용하며, 언더스코어나 대문자를 피하는 것이 관례입니다. 모듈 경로와 패키지 경로를 일관되게 유지하면 import 경로가 명확해지며, Go의 모듈 시스템이 패키지를 올바르게 식별할 수 있습니다.

## 코드 설명
제공된 코드 예제는 모듈 관리의 핵심 개념을 단계별로 설명하는 출력 위주의 예제입니다. 각 섹션은 실제 명령어와 파일 구조의 개념을 시뮬레이션하여 보여줍니다.

1. **go.mod 파일 생성 예시**: `go mod init` 명령어가 생성하는 파일의 구조와 `require` 섹션을 보여줍니다.
2. **go.sum 파일 설명**: 의존성 해시값 저장 방식과 보안 목적을 설명합니다.
3. **내부 패키지 (internal)**: 모듈 내부에서만 접근 가능한 패키지의 경로와 장점을 설명합니다.
4. **replace 지시어**: `go.mod` 파일에서 의존성을 교체하는 구문과 사용 사례를 보여줍니다.
5. **패키지 네이밍 관례**: 소문자, 간결성, 중복 제거 등 Go의 패키지 네이밍 규칙을 요약합니다.
6. **vendor 디렉토리**: `go mod vendor` 명령어의 효과와 CI 환경에서의 장단점을 설명합니다.
7. **모듈 경로 중요성**: 모듈 경로가 import 경로에 미치는 영향과 모듈 식별 방식을 설명합니다.

## 핵심 포인트
- `go.mod`는 모듈 메타데이터와 의존성 목록을, `go.sum`은 의존성 무결성 검증용 해시값을 관리합니다.
- `internal` 디렉토리의 패키지는 외부 모듈에서 import할 수 없어 모듈 API의 안정성을 보장합니다.
- `replace` 지시어는 의존성 버전을 로컬 경로나 특정 버전으로 교체할 수 있으며, 핫픽트 적용에 유용합니다.
- `go mod tidy`는 사용하지 않는 의존성을 제거하고 누락된 의존성을 추가하여 `go.mod` 파일을 정리합니다.
- 패키지 네이밍은 소문자, 간결성, 일관성을 지키며, 모듈 경로와 패키지 경로를 일치시키는 것이 좋습니다.
