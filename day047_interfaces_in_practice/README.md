# Day 47: 인터페이스 실전 패턴

## 개념 설명

Go 언어의 인터페이스는 타입을 종속시키는 것이 아니라 **행위(Action)**를 기준으로 시스템 구성 요소들을 느슨하게 결합하는 강력한 도구입니다.effective Go 문서와 실전 코드에서 가장 많이 접하는 패턴은 크게 세 가지로 정리할 수 있습니다.

첫째, `io.Reader`와 `io.Writer`입니다. 데이터가 어디서 오고 어디로 가는지와는 상관없이 데이터 스트림을 다루는 핵심 행위를 추상화한 표준 인터페이스입니다. 이 인터페이스를 이해하면 Go의 입출력 라이브러리를 자유자재로 다룰 수 있습니다.

둘째, 인터페이스 분리 원칙(ISP: Interface Segregation Principle)입니다. 특정 타입이 실제로 사용하지 않는 메서드가 인터페이스에 포함되어서는 안 됩니다. Go는 컴파일 타임에 구조체 메서드가 인터페이스의 메서드와 일치하는지 자동으로 확인하므로, 타입을 수정하지 않고도 필요한 행동만 모은 작은 인터페이스를 쉽게 정의할 수 있습니다.

셋째, "인터페이스를 받고, 구조체를 반환한다(Accept interface, return struct)" 원칙입니다. 함수나 메서드의 **입력 파라미터는 추상화(인터페이스)**를 받아서 유연성을 극대화하고, **출력값은 구체화(구조체)**를 반환하여 타입 정보의 명확성을 유지합니다.

## 코드 설명

1.  **io.Reader 패턴 (`ReadString` 함수)**
    *   `io.Reader` 인터페이스를 인자로 받아서 데이터 읽기 전용 함수를 구현했습니다. `strings.NewReader`는 이 인터페이스를 자동으로 만족하므로 별도의 변환 없이 함수에 바로 전달할 수 있습니다.
2.  **io.Writer 패턴 (`WriteString` 함수)**
    *   `io.Writer` 인터페이스를 인자로 받아 데이터 쓰기 전용 함수를 구현했습니다. `os.Stdout`과 `&bytes.Buffer` 모두 이 인터페이스를 구현하므로, 같은 함수를 통해 표준 출력과 메모리 버퍼에 데이터를 쓸 수 있습니다.
3.  **ISP 및 Accept interface return struct (`CleanRoom`, `CleanHouse` 함수)**
    *   `CleanRoom`이라는 작은 인터페이스를 정의하고, 진공청소기(`VacuumCleaner`)와 빗자루(`Broom`) 구조체에 `Clean` 메서드를 구현하여 자동으로 만족하게 했습니다.
    *   `CleanHouse` 함수는 구체적인 청소도구(구조체)를 받는 것이 아니라, `CleanRoom` 인터페이스를 받습니다. 이렇게 하면 진공청소기가 아닌 다른 새로운 청소 도구도 기존 코드를 수정하지 않고 손쉽게 추가할 수 있습니다.

## 핵심 포인트

*   **io.Reader / io.Writer**: 데이터의 원천(Source)이나 목적지(Destination)에 종속되지 않고, 스트림 데이터를 다루는 가장 기본적이고 유용한 인터페이스입니다.
*   **Accept Interface, Return Struct**: 의존성 주입을 통해 코드의 유연성(입력)을 극대화하고, 반환값을 통해 호출처의 타입 안전성(출력)을 확보하는 Go의黃金法则입니다.
*   **ISP (인터페이스 분리 원칙)**: 타입은 자신이 필요로 하는 최소한의 인터페이스만 구현하면 됩니다. Go 컴파일러가 이를 자동으로 검증하므로, 불필요한 메서드 의존성을 쉽게 제거할 수 있습니다.
