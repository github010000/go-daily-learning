>
> `vet: ./main.go:42:5: declared and not used: v`  

## 한 줄 요약
`if v, err := f(); err != nil` 패턴은 **에러 처리와 변수 선언을 한 번에** 처리하면서, 변수의 범위를 `if` 블록 안으로 제한하여 코드를 깔끔하게 유지하는 Go의 핵심 관용구입니다.

## 왜 필요한가
다른 언어(Python, JavaScript, Java)에서는 에러를 예외(Exception)로 처리하거나, 에러 객체를 별도로 반환받는 경우가 많습니다. Go는 에러를 **값**으로 처리합니다. 따라서 `f()`라는 함수를 호출할 때, 반환값이 `(결과, 에러)` 쌍이라면, 이 두 값을 동시에 다뤄야 합니다.

여기서 중요한 문제는 **변수의 범위**입니다. 만약 `v`와 `err`를 `if` 문 외부에 미리 선언하면, 에러가 발생했을 때도 `v`가 초기화되지 않은 상태(영변수)로 남을 수 있어 버그의 원인이 됩니다. 반면, `if` 내부에서 `:=` 를 사용하면 `v`와 `err`는 `if` 블록 안에서만 살아있으므로, 블록을 벗어나면 자연스럽게 잊혀집니다.

Go가 이 패턴을 강력히 권장하는 이유는 **명확성**입니다. "이 변수는 에러가 없을 때만 유효합니다"라는 의도를 코드 자체로 표현할 수 있습니다. Python의 `try-except`나 Java의 `if (exception != null)`과 달리, Go는 에러를 **첫 번째 반환값이 아닌 두 번째 반환값**으로 처리하여, 에러 체크를 강제합니다.

## 기본 사용
가장 일반적인 형태는 다음과 같습니다.

```go
v, err := someFunction()
if err != nil {
    // 에러 처리 (로그 기록, 반환, 리트리 등)
    return err
}
// 여기부터 v를 안전하게 사용할 수 있습니다.
fmt.Println("성공:", v)
```

핵심은 **`:=` 연산자**입니다. `:=` 는 변수를 선언하면서 동시에 할당합니다. `if v, err := f(); err != nil` 에서 `v`와 `err`는 `if` 문이 시작되는 시점에 선언되며, 그 범위는 `if` 블록과 `else` 블록(있는 경우) 안에서만 유효합니다.

```go
// 변수 범위 시연
if x, ok := map[string]int{"a": 1}["b"]; ok {
    fmt.Println(x) // 사용 가능
}
// fmt.Println(x) // 컴파일 에러: x undefined
```

## 실전에서는 이렇게 쓴다
실제 Go 코드에서 이 패턴은 거의 모든 곳에서 발견됩니다.

**1. 파일 읽기 (표준 라이브러리)**
```go
data, err := os.ReadFile("config.json")
if err != nil {
    log.Fatalf("설정 파일 읽기 실패: %v", err)
}
```
`os.ReadFile` 는 `([]byte, error)` 를 반환합니다. 에러가 없으면 `data` 를 바로 사용할 수 있습니다.

**2. HTTP 요청 (외부 패키지)**
```go
resp, err := http.Get("https://example.com")
if err != nil {
    log.Fatal(err)
}
defer resp.Body.Close()
```
`http.Get` 도 동일하게 `(Response, error)` 를 반환합니다.

**3. 맵에서 값 가져오기**
```go
v, ok := m["key"]
if !ok {
    return errors.New("key not found")
}
```
맵 조회 시 두 번째 반환값 `ok` 를 이용해 키 존재 여부를 확인합니다. 이 경우 `err` 대신 `ok` 를 사용합니다.

## 흔한 실수

### 1. 변수 범위를 벗어나서 사용하기

**무엇을 했는지:** `if` 안에서 선언한 변수를 `if` 바깥에서 사용하려 합니다.

```go
// 틀린 코드
if v, err := someFunc(); err != nil {
    return err
}
fmt.Println(v) // 컴파일 에러: undefined: v
```

**어떤 일이 벌어지는지:** 컴파일러가 `v`를 인식하지 못합니다. `if` 블록은 하나의 스코프이므로, 안쪽에 선언된 변수는 밖으로 나오지 않습니다.

**왜 그런지:** Go는 변수의 수명을 명확히 하기 위해 블록 스코프를 엄격하게 적용합니다. `v`는 `if` 블록 내에서만 "생존"합니다.

**고친 코드:**
```go
var v int
if v, err := someFunc(); err != nil {
    return err
}
// v는 바깥에서 선언했으므로 접근 가능 (하지만 에러 시에는 영변수일 수 있음)
fmt.Println(v)
```
또는, `v`가 `if` 안에서만 필요하다면 밖으로 빼지 않고 `if` 안에서 처리합니다.

### 2. else 를 남용해 코드가 깊어지기

**무엇을 했는지:** 모든 경우에 `else` 를 붙여 중첩을 만듭니다.

```go
// 틀린 코드 (Go 스타일 아님)
if v, err := someFunc(); err != nil {
    return err
} else if v <= 0 {
    return errors.New("v must be positive")
} else {
    // 정상 로직 (여기가 깊어짐)
    doSomething(v)
    if err := anotherFunc(v); err != nil {
        return err
    }
}
```

**어떤 일이 벌어지는지:** 코드가 트리처럼 가지치기 됩니다. `else` 가 많아질수록 정상 로직이 점점 더 안으로 파고듭니다.

**왜 그런지:** Go 커뮤니티는 **Early Return** 패턴을 선호합니다. 실패 케이스를 빠르게 반환하여, 정상 로직이 최상위 들여쓰기에 위치하도록 합니다.

**고친 코드:**
```go
// 고친 코드 (Early Return)
v, err := someFunc()
if err != nil {
    return err
}
if v <= 0 {
    return errors.New("v must be positive")
}
// 정상 로직 (들여쓰기 증가 없음)
doSomething(v)
if err := anotherFunc(v); err != nil {
    return err
}
```

### 3. := 와 = 의 혼동 (재할당 실수)

**무엇을 했는지:** 이미 선언된 변수를 `:=` 로 다시 선언하려 합니다.

```go
// 틀린 코드
x := 10
x := 20 // 컴파일 에러: no new variables on left side of :=
```

**어떤 일이 벌어지는지:** 컴파일 에러가 납니다. `:=` 는 최소한 하나의 새로운 변수를 선언해야 합니다.

**왜 그런지:** `:=` 는 "새로운 변수 선언 + 할당"의 의미입니다. 기존 변수만 재할당하려면 `=` 를 써야 합니다.

**고친 코드:**
```go
x := 10
x = 20 // 재할당
```

혹은, 여러 변수 중 일부만 새로운 경우:
```go
x := 10
x, y := 20, 30 // x는 재할당, y는 새로 선언 (컴파일 됨)
```

### 4. 에러를 무시하고 변수만 사용하기

**무엇을 했는지:** `err` 를 무시하고 `v` 만 사용합니다.

```go
// 틀린 코드
v, _ := someFunc() // 에러를 무시함
fmt.Println(v) // v가 영변수일 수 있음!
```

**어떤 일이 벌어지는지:** 함수가 에러를 반환했더라도 `v` 는 영변수(0, "", nil 등)일 수 있습니다. 이를 무시하면 논리 버그가 생깁니다.

**왜 그런지:** Go는 에러를 값으로 취급하므로, 에러를 무시하는 것은 **의도적 선택**이어야 합니다. `_` 를 사용한다는 것은 "에러를 알지만 무시한다"는 명시적인 의사 표현입니다.

**고친 코드:**
```go
v, err := someFunc()
if err != nil {
    // 에러 처리 (로깅, 반환, 리트리 등)
    return err
}
fmt.Println(v)
```

## 주의할 점

### 1. `if` 내부 변수는 `else` 블록에서도 사용 불가
```go
if v, err := f(); err != nil {
    // err 사용 가능
} else {
    // v 사용 가능 (if 블록과 else 블록은 같은 스코프 공유)
}
```
참고로 `if` 와 `else` 는 **같은 스코프**를 공유합니다. 따라서 `v` 는 `else` 안에서도 사용할 수 있습니다. 하지만 `if` 블록 안에서만 선언된 변수는 `else` 밖으로는 나갈 수 없습니다.

### 2. `:=` 는 항상 새 변수를 생성하지 않음
```go
x := 1
x, y := 2, 3 // x는 재할당, y는 새로 선언
```
`:=` 의 왼쪽에 **최소한 하나의 새 변수**가 있어야 합니다. 모두 기존 변수라면 컴파일 에러가 납니다.

### 3. 에러 변수의 이름은 `err` 가 관례
```go
if v, err := f(); err != nil { ... }
```
`err` 라는 이름은 Go 커뮤니티의 표준입니다. 다른 이름을 쓰면 코드가 읽기 어려워집니다.

### 4. Go 1.22 이전의 루프 변수 공유 문제 (참고)
`for` 루프 안에서 `if` 를 쓸 때, 이전 Go 버전에서는 루프 변수가 공유되어 버그가 생길 수 있었습니다. Go 1.22부터는 자동으로 새로 선언되므로 걱정 없습니다.
