# Day 55: 미니 CLI 도구 제작

## 개념 설명
CLI(명령줄 인터페이스) 도구를 개발할 때는 사용자의 입력을 정확히 해석하여 적절한 동작을 수행해야 합니다. Go 표준 라이브러리인 `flag` 패키지는 명령어 인자를 파싱하는 가장 표준적인 방법이지만, 기본 `flag.CommandLine`은 단일 실행 파일용입니다. 실제 상용 CLI 도구(예: git, docker, curl)는 서브커맨드(Subcommand) 패턴을 사용하므로, `os.Args` 슬라이스를 직접 확인하여 하위 명령어별로 라우팅하는 구조가 필요합니다.

서브커맨드 패턴을 구현할 때는 `flag.NewFlagSet`을 사용합니다. 이 객체는 전역 인자와 독립적인 인자 파싱 컨텍스트를 제공하며, 각 서브커맨드마다 별도의 플래그 정의가 가능합니다. `flag.ContinueOnError` 옵션을 사용하면 인자 파싱 실패 시 자동으로 종료되지 않고 에러 객체를 반환하므로, 호출 측에서 `os.Exit`를 통해 종료 코드를 세밀하게 제어할 수 있습니다.

`os.Exit` 함수는 프로그램의 종료를 명시적으로 제어하며, 표준 관례에 따라 성공 시 `0`, 실패 시 `1` 이상의 코드를 반환합니다. 이 종료 코드는 쉘 스크립트나 파이프라인에서 프로그램의 실행 상태를 검증하거나 조건부 분기(예: `&&`, `||`)를 수행할 때 활용됩니다. `main` 함수의 진입점에서 모든 서브커맨드의 반환 값을 집계한 후 단일 `os.Exit`로 호출하면 종료 코드 관리가 일관되게 유지됩니다.

## 코드 설명
- **main 함수 진입로**: `len(os.Args) < 2` 체크로 최소 실행 조건을 검증하고, `os.Exit(1)`로 즉시 종료합니다. `os.Args[1]`을 기준으로 `switch` 문을 통해 `greet`, `version`, `help` 하위 함수로 분기하며, 반환된 코드를 `exitCode`에 저장합니다.
- **flag.NewFlagSet 활용**: `handleGreet` 함수에서 `flag.NewFlagSet("greet", flag.ContinueOnError)`를 생성합니다. `-name` 플래그를 정의한 후 `fs.Parse(os.Args[2:])`로 서브커맨드 이후의 인자만 파싱합니다. 에러 발생 시 `1`을 반환하여 `main`에서 `os.Exit(1)`로 이어집니다.
- **종료 코드 통합 관리**: 각 하위 함수는 `int` 타입으로 성공(`0`) 또는 실패(`1`) 코드를 반환합니다. `main` 함수의 마지막에서 `os.Exit(exitCode)`를 호출하여 프로세스 종료 상태를 일원화합니다.

## 핵심 포인트
- `os.Args` 기반 라우팅과 `switch` 문을 활용하여 확장 가능한 서브커맨드 패턴 구조 구현
- `flag.NewFlagSet`을 사용하여 전역 인자 공간과 서브커맨드 인자 공간을 명확히 분리
- `flag.ContinueOnError` 옵션으로 인자 파싱 실패 시 호출 측으로 에러 전달, `os.Exit`로 종료 코드 중앙 관리
- `os.Exit(0)` 및 `os.Exit(1)` 패턴을 통해 외부 스크립트 호환성 보장
