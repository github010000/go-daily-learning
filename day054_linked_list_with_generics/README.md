# Day 54: 제네릭으로 연결 리스트 구현

## 개념 설명 섹션
제네릭(Generic)은 Go 1.18에서 정식 도입된 기능으로, 특정 타입에 종속되지 않는 재사용 가능한 코드와 자료구조를 정의할 수 있게 해줍니다. 기존 Go에서는 `interface{}`를 사용해 모든 타입을 수용했으나, 이는 런타임에서 타입을 확인하거나 단언(type assertion)해야 하는 번거로움과 타입 안전성 부족 문제를 일으켰습니다. 제네릭을 사용하면 컴파일 단계에서 타입 파라미터를 명시함으로써 타입 오류를 조기에 발견하고, 가독성과 실행 효율성을 모두 높일 수 있습니다.

연결 리스트(Linked List)는 노드(Node)들이 포인터로 연결되어 선형적으로 데이터를 저장하는 자료구조입니다. 각 노드는 데이터를 담는 필드와 다음 노드를 가리키는 필드로 구성되며, 필요에 따라 이전 노드를 가리키는 필드를 추가해 doubly linked list로 확장할 수 있습니다. 제네릭을 적용하면 정수, 문자열, 구조체 등 다양한 타입에 대해 동일한 로직의 연결 리스트를 재사용할 수 있으며, 타입 인스턴스가 생성될 때 컴파일러가 해당 타입에 맞는 코드를 자동으로 생성합니다.

이 실습에서는 제네릭 타입 파라미터 `[T any]`를 활용해 `Node`와 `LinkedList`를 구현합니다. `PushBack`으로 끝값 추가, `PopBack`으로 끝값 제거, `PeekFront`로 앞값 확인, `Len`으로 길이 계산, `ForEach`로 순회 기능을 구현하며, 제네릭의 실전 활용법을 직접 체험해 봅니다.

## 코드 설명 섹션
- **Node[T any] 구조체**: 제네릭 타입 파라미터 `T`를 사용하여 값(`Value`)과 다음 노드 포인터(`Next`)를 정의합니다. `any`는 `interface{}`의 별칭으로, 모든 타입을 허용함을 의미합니다.
- **LinkedList[T any] 구조체**: 리스트의 시작 노드(`Head`)와 현재 요소 수(`Length`)를 관리합니다. 제네릭을 통해 타입을 추상화하여 재사용성을 극대화합니다.
- **핵심 메서드들**: `PushBack`은 끝 노드를 찾아 새 노드를 연결하고 길이를 증가시킵니다. `PopBack`은 마지막 두 노드 사이를 끊거나 단일 노드일 경우 예외 처리를 합니다. `PeekFront`와 `Len`은 각각 첫 번째 값과 길이를 반환하며, 제네릭이므로 반환 타입도 `T` 또는 `int`로 자연스럽게 추론됩니다.
- **ForEach 메서드**: 함수형 프로그래밍 패러다임을 반영해 리스트 순회 로직을 캡슐화합니다. 호출 시 전달된 콜백 함수에 각 요소의 값을 안전하게 전달합니다.
- **main 함수**: `int`와 `string` 타입으로 각각 인스턴스를 생성하여 메서드 호출과 출력 결과를 검증합니다. 컴파일 시 각 제네릭 인스턴스에 맞는 코드가 생성됨을 확인할 수 있습니다.

## 핵심 포인트 섹션
- 제네릭 타입 파라미터 `[T any]`를 사용하면 컴파일 시점의 타입 안전성을 유지하면서 자료구조의 재사용성을 확보할 수 있습니다.
- 기존 `interface{}` 방식과 달리 타입 단언(type assertion)이 필요 없으며, 메서드 시그니처가 직관적으로 정리됩니다.
- 연결 리스트의 핵심 연산(Push/Pop/Peek/Length/Iteration)을 제네릭으로 추상화하면 다른 타입에도 동일하게 적용 가능합니다.
- 제네릭 함수와 메서드는 호출 시 타입을 명시하거나 컴파일러가 추론하게 함으로써 타입 추론(Type Inference)을 자연스럽게 활용합니다.
