# Day 59: 의존성 주입 패턴

## 개념 설명
의존성 주입(Dependency Injection, DI)은 객체가 직접 자신의 의존성(다른 객체, 외부 서비스 등)을 생성하거나 찾는 대신, 외부에서 의존성을 제공받도록 하는 디자인 패턴입니다. Go 언어에서는 `interface` 기반 추상화와 생성자 주입(Constructor Injection)을 통해 이를 자연스럽고 명확하게 구현할 수 있으며, 이는 코드 결합도를 낮추고 유지보수성을 극대화하는 핵심 기법입니다.

인터페이스 기반 DI의 핵심은 '구체적인 구현체가 아닌 인터페이스를 의존성으로接受한다'는 점입니다. Effective Go에서도 강조하듯, Go의 인터페이스는 암시적 구현을 지원하므로 코드를 작성할 때 미리 구체적인 구조체를 정의하지 않고도 유연한 의존성 관계를 설계할 수 있습니다. 이로 인해 외부 라이브러리가 변경되거나 프로토콜이 업데이트되더라도 핵심 로직을 수정하지 않고도 쉽게 대응할 수 있습니다.

테스트 가능성(Testability)은 DI의 가장 큰 장점 중 하나입니다. 네트워크 호출이나 파일 I/O, DB 접속 등 비결정적 결정 요인에 의존하는 코드는 단위 테스트가 어렵습니다. 생성자 주입을 사용하면 실제 구현체 대신 `Mock`이나 `Stub` 같은 테스트 더블을 주입하여, 외부 상태 변화와 무관하게 단위 테스트를 안정적이고 빠르게 수행할 수 있습니다.

Go 생태계에는 `wire`, `fx`와 같은 DI 프레임워크도 존재하지만, 대부분의 실무 프로젝트에서는 `wire 없이 수동으로 생성자 함수를 호출하며 객체 그래프를 연결`하는 방식을 선호합니다. 이는 실행 흐름을 명확하게 추적 가능하게 하고, 불필요한 컴파일러 지시나 런타임 오버헤드를 방지하기 위한 Go적인 철학에 부합합니다.

## 코드 설명
- **의존성 추상화**: `Storage` 인터페이스를 정의하여 데이터 조회 및 저장을 추상화합니다.
- **구현체 분리**: `SQLiteStorage`는 실제 프로덕션 환경용, `MockStorage`는 테스트 환경용 구현체입니다.
- **생성자 주입**: `NewUserService` 함수가 `Storage` 인터페이스를 매개변수로 받아 구조체에 주입합니다.
- **수동 DI 연결**: `main()` 함수에서 `wire` 같은 프레임워크 없이 직접 객체를 생성하고 연결(Object Graph 구성)하여 프로덕션과 테스트 환경을 분리합니다.

## 핵심 포인트
- Go는 암시적 인터페이스를 통해 외부 패키지 의존 없이도 유연한 DI 구조를 쉽게 구현할 수 있습니다.
- 생성자 주입(Constructor Injection)은 테스트 가능성 향상과 결합도 감소에 가장 효과적입니다.
- 복잡한 객체 그래프 관리에는 `wire` 도구를 활용할 수 있으나, 일반적으로 수동 DI가 Go의 명시적 흐름 철학에 부합합니다.
- 테스트 더블(Mock/Stub) 작성을 통해 외부 시스템 의존성 없이도 단위 테스트의 결정적 실패를 예방할 수 있습니다.
