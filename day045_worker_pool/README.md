# Day 45: 워커 풀(Worker Pool)

## 개념 설명 섹션

워커 풀(Worker Pool)은 제한된 수의 고루틴(워커)을 재사용하여 작업을 처리하는 대표적인 동시성 패턴입니다. 무제한으로 고루틴을 생성하면 운영체제 스케줄링 오버헤드가 증가하고 메모리 소모가 급증할 수 있으므로, 풀(Pool)을 통해 동시에 실행되는 고루틴의 개수를 제한하여 리소스를 효율적으로 관리합니다.

핵심 구조는 작업 채널(Job Channel)과 결과 채널(Result Channel)입니다. 메인 고루틴이 작업 채널에 데이터를 넣으면, 워커들은 이 채널에서 작업을 꺼내 처리한 후 결과 채널로 보냅니다. 채널이 닫히면 워커 내 `range` 루프가 자연스럽게 종료되며, 이는 고루틴의 안전한 생명주기 관리를 가능하게 합니다.

`golang.org/x/sync/errgroup` 패키지는 여러 고루틴을 그룹화하고 에러를 일괄 처리하는 데 특화되어 있습니다. 각 워커 함수를 `eg.Go()`에 등록하면, 모든 워커가 종료된 후 `eg.Wait()`를 호출하여 에러를 통합 검증할 수 있어 에러 처리 코드가 간결해집니다. 이 패턴은 HTTP 서버의 리퀘스트 처리, 배치 데이터 파싱, API 병렬 호출 등 제한된 리소스 안에서 병렬 처리가 필요한场景中 널리 사용됩니다.

## 코드 설명 섹션

- **채널 초기화**: `jobs`와 `results` 채널을 버퍼 크기 `numJobs`로 생성하여 작업 투입과 결과 수집 중 일시적인 블로킹을 방지합니다.
- **워커 풀 생성**: `for` 문으로 `numWorkers`만큼 고루틴을 실행합니다. `eg.Go()`에 익명 함수를 전달하여 워커의 실행 로직과 에러 반환을 등록합니다. Go 1.22 미만 호환성을 위해 루프 변수 `w`를 복사하여 사용합니다.
- **작업 흐름 제어**: 작업 채널로 데이터를 투입하는 별도 고루틴에서 `close(jobs)`를 호출합니다. `wg.Wait()`로 워커 완료 대기 후 `close(results)`를 호출하면, 결과 채널 읽기 루프(`for res := range results`)가 정상적으로 종료됩니다.
- **에러 검증**: `eg.Wait()`는 등록된 모든 고루틴이 종료될 때까지 메인 고루틴을 블로킹합니다. 고루틴 내에서 에러가 발생하면 `errgroup`이 이를 캡처하여 반환하므로, 마지막에서 일괄 검증합니다.

## 핵심 포인트 섹션

- 제한된 수의 워커 고루틴을 재사용하여 동시성 레벨을 통제하고 시스템 리소스 소모를 최적화합니다.
- 작업 채널과 결과 채널을 연결하여 고루틴 간 안전한 데이터 흐름과 자동화된 동기화를 구현합니다.
- `errgroup.Go()`를 사용해 고루틴 생명주기를 통합 관리하고 에러를 일괄 캡처하여 코드의 가독성을 높입니다.
- `close()` 호출 시점을 정확히 제어해야 `range` 루프가 무한 대기하거나 데드락이 발생하지 않습니다.
