# Day 44: 채널 고급 패턴

## 개념 설명
채널은 Go 언어의 병렬 처리를 위한 핵심 도구이며, 단순한 데이터 전송을 넘어 시스템 아키텍처를 설계하는 데 널리 쓰입니다. **Fan-out/Fan-in** 패턴은 작업을 여러 고루틴으로 분산 처리한 후, 결과를 단일 채널로 모아서 후속 처리하는 방식입니다. 이는 CPU 코어를 최대한 활용하면서도 결과를 한곳에서 집계해야 할 때 유용합니다. **Pipeline**은 여러 단계를 채널로 연결해 데이터를 단계별로 변환하는 패턴으로, 각 단계가 독립적으로 동작하면서도 흐름을 유지하게 해 코드의 가독성과 확장성을 높입니다.

**Done 채널**은 병렬 작업을 안전하게 취소하거나 종료하기 위한 표준 관행입니다. Go는 채널을 닫는 것만으로 신호를 전달할 수 있지만, 취소의 경우 `struct{}` 채널을 사용해 명시적으로 제어합니다. 각 고루틴은 `select` 구문으로 done 채널의 닫힘 신호를 감지하고, 작업 중이던 채널을 닫거나 반환함으로써 리소스 누수를 방지합니다. 이는 특히 네트워크 요청이나 장기 실행 작업에서 필수적입니다.

**세마포어 패턴**은 제한된 자원(예: 동시 DB 연결, API 호출 제한)에 접근하는 고루틴의 수를 조절합니다. 버퍼가 있는 채널을 세마포어처럼 사용하고, 고루틴이 작업을 시작할 때 채널에 값을 보내고 완료 시 값을 꺼내어 반납하는 방식으로 동시성을 제어합니다. 이 패턴은 `sync.WaitGroup`과 결합하면 깔끔하게 리소스 관리를 할 수 있으며, 과부하로 인한 시스템 장애를 미리 막는 데 효과적입니다.

## 코드 설명
- **fanOutFanIn 함수**: `nums` 배열의 각 요소를 고루틴으로 분할 처리합니다. `sync.WaitGroup`으로 고루틴 완료를 추적하고, `wg.Wait()` 이후 `out` 채널을 닫아 `range` 루프가 자연스럽게 종료되도록 합니다. `select`를 통해 done 채널의 취소 신호를 우선적으로 처리합니다.
- **pipeline 함수**: 입력 채널을 읽고 조건부 변환 후 새로운 출력 채널로 전달합니다. `defer close(out)`를 통해 고루틴 종료 시 채널을 반드시 닫으며, `select`를 사용해 취소 신호가 오면 즉시 중단됩니다.
- **done 채널 활용**: 3번 섹션에서 `doneCancel` 채널을 사용해 작업 중단을 시뮬레이션합니다. `close(doneCancel)`가 호출되면 pipeline 내부의 `select`가 즉시 `case <-done:` 분기로 이동해 고루틴을 정리합니다.
- **semaphorePattern 함수**: 버퍼 크기 2인 채널 `sem`을 세마포어로 사용합니다. `sem <- struct{}{}`로 진입, `defer func() { <-sem }()`로 항상 반납되도록 보장합니다. `sync.Mutex`와 `sync.WaitGroup`을 결합해 슬라이스 결과 수집과 고루틴 종료를 안전하게 처리합니다.

## 핵심 포인트
- 채널은 항상 생성한 쪽에서 닫아야 하며, 수신자는 `range`를 사용해 채널 닫힘을 자동으로 감지하세요.
- 취소 패턴은 `done chan struct{}`을 사용하고, 모든 고루틴의 루프와 `select`에서 이를 반드시 확인해야 누수가 방지됩니다.
- 세마포어는 버퍼가 있는 채널로 구현하며, `defer`를 활용해 예외 상황에서도 반드시 리소스를 반납하세요.
- 파이프라인은 단계를 함수로 분리하면 테스트와 재사용이 용이해지며, 단계 간 채널은 반드시 닫히도록 설계하세요.
- `sync.WaitGroup`과 채널을 병행 사용할 때는 WaitGroup으로 고루틴 완료를 추적하고, 채널로 결과나 신호를 전달하는 것이 Go의 표준 관행입니다.
