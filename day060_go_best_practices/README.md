# Day 60: Go 관용구와 Best Practices

## 개념 설명
Go 언어는 문법적 단순함을 지향하며, 이를 통해 코드의 명확성과 유지보수성을 극대화합니다. Effective Go는 이러한 철학을 실천하는 관용구(Idioms)와 Best Practices를 체계적으로 정리한 공식 문서입니다. 에러 처리, 패키지 설계, 문서화 관례를 준수하면 팀 개발 효율과 소프트웨어의 신뢰성을 동시에 높일 수 있습니다.

에러 처리는 Go의 가장 큰 특징 중 하나로, 명시적 에러 반환을 지향합니다. 에러는 함수의 마지막 반환값으로 전달하며, 발생 시 즉시 early return하여 코드 블록의 중첩을 피합니다. `errors.Is`와 `errors.As`를 활용하면 에러 체이닝과 타입 검사를 안전하고 유연하게 처리할 수 있습니다. 커스텀 에러 타입을 정의할 때는 `Error() string` 메서드를 구현하여 표준 `error` 인터페이스를 만족시키는 것이 관례입니다.

패키지 설계에서는 '단일 책임 원칙'과 '간단한 인터페이스'가 핵심입니다. 인터페이스는 필요한 최소한의 메서드만 포함해야 하며, 추상화가 지나치면 오히려 유연성이 떨어집니다. 또한 `godoc` 형식 주석은 API의 공식 문서로 자동 생성되므로, export된 함수나 타입에 명확한 설명을 남기는 것이 필수적입니다. Go Proverbs와 코드 리뷰 체크리스트는 이러한 원칙을 일상적으로 실천하도록 돕는 실용적인 가이드입니다.

## 코드 설명
- `UserNotFoundError`: 커스텀 에러 타입으로 `Error()` 메서드를 구현하여 표준 `error` 인터페이스를 만족시킵니다.
- `FindUser`: 에러 발생 시 `nil`과 함께 에러를 반환하고, 호출부는 `if err != nil`에서 즉시 처리합니다.
- `GetDisplayName`: nil 체크와 단순 조건문으로 가독성을 높이고, 불필요한 중첩을 제거했습니다.
- `main`: `errors.As`를 사용한 타입 단언, early return 패턴, 그리고 Proverbs를 출력하여 관용구를 종합적으로 시연합니다.

## 핵심 포인트
- 에러는 마지막 반환값이며, `if err != nil`에서 즉시 반환하여 중첩을 최소화합니다.
- 커스텀 에러는 `Error() string` 인터페이스를 구현하고, `errors.Is/As`로 검사합니다.
- 인터페이스는 최소화하며, export된 코드는 `godoc` 주석으로 명확히 문서화합니다.
- 코드는 'clever'보다 'clear'해야 하며, 코드 리뷰 시 일관성 유지가 최우선입니다.
